## Часть 1. Класс `Money`

### Требования к структуре
- Класс **`final`** (нельзя наследовать).
- Поля **`private final`**: `BigDecimal amount` и валюта (тип — на твой выбор: `String` код или `enum Currency`; обоснуй выбор в комментарии).
- **Конструктор `private`** — извне не вызывается.
- **Никаких сеттеров.** Геттеры — возвращают значения, не дают мутировать состояние.
- `toString()` человекочитаемый: например `"19.99 EUR"`.
- `equals()` и `hashCode()` — пока **не обязательно** (полноценно разберём в Модуле 3), но подумай: два `Money` с одинаковой суммой и валютой — равны? Можешь оставить TODO-комментарий.

### Фабричные методы (вход → выход)

```java
// Вход: сумма строкой ("19.99") + код валюты ("EUR")
// Выход: новый Money. Строку парсим в BigDecimal (НЕ через double!)
public static Money of(String amount, String currency)

// Вход: сумма как long в МИНОРНЫХ единицах (центах) + валюта
//   Пример: ofMinor(1999, "EUR") → 19.99 EUR
// Выход: новый Money. Это удобный и безопасный путь (целые центы, без дробей)
public static Money ofMinor(long minorUnits, String currency)
```

> Подумай: почему два разных фабричных метода лучше двух перегруженных конструкторов? (Подсказка: у методов есть **имена** — `of` vs `ofMinor` читаются по-разному, а `Money(String,...)` vs `Money(long,...)` различаются только типом и путают.)

### Операции (неизменяемость в действии)

```java
// Вход: другой Money той же валюты
// Выход: НОВЫЙ Money с суммой this+other. this НЕ меняется.
// Если валюты разные → бросить IllegalArgumentException
public Money add(Money other)

// Вход: целочисленный множитель
// Выход: НОВЫЙ Money. this не меняется.
public Money multiply(int factor)
```

**Контракт неизменяемости, который надо продемонстрировать:**
```java
Money a = Money.of("10.00", "EUR");
Money b = a.add(Money.of("5.00", "EUR"));
// После этого: a == "10.00 EUR" (НЕ изменился), b == "15.00 EUR"
```

### Валидация (краевые случаи — обязательно обработать)
| Вход | Ожидаемое поведение |
|---|---|
| `of(null, "EUR")` | `NullPointerException` или `IllegalArgumentException` (выбери и обоснуй) |
| `of("abc", "EUR")` | поймать `NumberFormatException`, бросить осмысленное исключение |
| `of("10.00", null)` | отказ с понятным сообщением |
| `add()` разных валют | `IllegalArgumentException("currency mismatch: EUR vs USD")` |
| отрицательная сумма | **реши сам**: разрешать (для возвратов/долгов) или запрещать? Обоснуй в комментарии |

## Часть 2. Доказательство pass-by-value (главное)

Это ядро задания — показать на исполняемом коде разницу **мутация vs переприсваивание**, на которой ты спотыкался.

Напиши класс `PassByValueDemo` с тремя сценариями. Для каждого — вывод в консоль ДО и ПОСЛЕ вызова.

### Сценарий 1: неизменяемый `Money` нельзя «испортить» из метода
```java
// Метод пытается "изменить" Money. Покажи, что снаружи объект тот же.
static void tryToModify(Money m) {
    m = m.add(Money.of("100.00", "EUR"));   // переприсваивание ЛОКАЛЬНОЙ копии ссылки
}
// В main: создать Money "10.00 EUR", вызвать tryToModify, напечатать — должно остаться "10.00 EUR"
```
**Ожидаемый вывод:**
```
До:    10.00 EUR
После: 10.00 EUR   ← переприсваивание копии ссылки не видно снаружи
```

### Сценарий 2: изменяемый объект — мутация видна снаружи
Возьми **изменяемый** класс (например, простой `MutableBox` с полем `int value` и сеттером, или `StringBuilder`, или `int[]`).
```java
static void mutate(MutableBox box) {
    box.setValue(99);   // МУТАЦИЯ общего объекта через копию ссылки
}
```
**Ожидаемый вывод:**
```
До:    0
После: 99   ← мутация общего объекта видна снаружи
```

### Сценарий 3: переприсваивание того же изменяемого объекта — НЕ видно
```java
static void reassign(MutableBox box) {
    box = new MutableBox(99);   // переприсваивание копии ссылки, НЕ мутация
}
```
**Ожидаемый вывод:**
```
До:    0
После: 0   ← переприсваивание копии ссылки не видно снаружи
```

> Сценарии 2 и 3 — лакмус: один и тот же тип объекта, но `box.setValue()` (через ссылку) виден снаружи, а `box = new ...` (присваивание переменной) — нет. Именно это различие провалилось на примере с `int[]`. В комментариях к каждому сценарию объясни словами **почему** в терминах «копии ссылки» / «листка с адресом».
