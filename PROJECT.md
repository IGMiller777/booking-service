# booking-service: описание проекта

## Что это

`booking-service` — backend-сервис бронирования ресурсов. Под ресурсом понимается любая единица, которую можно забронировать на временной интервал: переговорная комната, рабочий стол в коворкинге, временной слот у специалиста, столик в ресторане.

Это **сквозной учебный проект**: каждая новая тема курса сразу применяется здесь. К концу — полноценный production-ready сервис, который можно показывать на собеседовании.

## Репозиторий

`IGMiller777/booking-service` на GitHub.

## Что должно получиться в итоге

Задеплоенный, покрытый тестами, защищённый REST API на Java + Spring Boot + PostgreSQL с асинхронными уведомлениями и разделением на сервисы.

Конкретно:
- REST API: создание, отмена, просмотр бронирований.
- Аутентификация и авторизация (JWT): пользователь видит и отменяет только свои брони.
- PostgreSQL как основное хранилище, JPA + Hibernate как ORM.
- Защита от двойного бронирования на уровне БД (блокировки) и бизнес-логики.
- Redis-кэш на запросы доступности слотов.
- Асинхронные уведомления через RabbitMQ (событие создания брони → уведомление пользователю).
- Поток событий в Kafka (`BookingCreated`, `BookingCancelled`) — задел под event-driven архитектуру.
- Разделение монолита на сервисы: `booking-service` + `notification-service`.
- Контейнеризация: `Dockerfile`, `docker-compose` для локального запуска всей системы.
- Покрытие тестами: юнит-тесты (JUnit 5 + Mockito) + интеграционные тесты (`@SpringBootTest`, Testcontainers).
- CI через GitHub Actions: тесты запускаются автоматически на каждый push.

## Доменная модель

**User** — пользователь системы. Поля: id, имя, email, пароль (хранится хешем), роль.

**Resource** — бронируемый ресурс. Поля: id, название, тип (комната/стол/слот), описание, активен ли.

**Booking** — бронирование. Поля: id, пользователь, ресурс, начало интервала, конец интервала, статус (PENDING / CONFIRMED / CANCELLED), дата создания.

**Money** — тип для денежных сумм. Неизменяемый. `BigDecimal` внутри, валюта (`MyCurrency` enum). Используется для цен, депозитов, штрафов за отмену.

## Структура пакетов (целевая)

```
com.booking
├── domain          # доменные классы: User, Resource, Booking, Money
├── repository      # репозитории (сначала файл, потом JDBC, потом JPA)
├── service         # бизнес-логика
├── controller      # REST-контроллеры
├── dto             # объекты запроса/ответа (records)
├── exception       # кастомные исключения
├── config          # конфигурация Spring, Security, Kafka и т.д.
└── BookingApplication.java
```
